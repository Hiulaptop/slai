## 4. Render/Download Tailwind Output

- [x] 4.1 Add a Tailwind-class rendering mode for text font-size/color in `modules/slides/domain/structured/render.ts`, additive to (not replacing) the existing inline-style output used by every other prop/element. Implemented as `renderStructuredRevisionWithTailwindClasses` (new export, alongside the unchanged `renderStructuredRevision`), reusing `tailwind-whitelist.ts`'s new reverse lookups (`classNameForFontSize`/`classNameForColor`) to regenerate a class from an already-resolved value.
- [x] 4.2 Add a compile step that invokes `@tailwindcss/cli` against the rendered HTML's classes and produces a stylesheet, embedded inline in the returned standalone document; scope this to the render/download route handlers only, not the general `renderStructuredRevision` entry point every other caller uses. Implemented as `modules/slides/infrastructure/structured/tailwind-compiler.ts` (spawns the CLI with `@source inline(...)` + `source(none)` - no automatic project-wide content scanning) and `render-standalone-html.ts` (orchestrates render+compile+embed, with a graceful fallback to plain inline styles if the compile step fails); wired into both `/api/slides/[id]/render` and `/api/slides/[id]/download` routes. Found and fixed two real bugs during implementation: (1) Tailwind v4's automatic content detection was scanning this whole project's source for classes rather than using only the explicit ones - fixed with `source(none)`; (2) Next.js/Turbopack's build-time bundler cannot trace a dynamically-computed `require()` path - fixed by resolving `@tailwindcss/cli`'s entry via plain `fs.readFileSync`, not `require`.
- [x] 4.3 Add tests: rendered/downloaded output for a generation with Tailwind-resolved text contains the expected utility classes and an embedded stylesheet covering them; the general render path used elsewhere is unaffected (still inline styles, no compile step invoked); a malformed stored value still fails closed per the existing "Render malformed stored structure" requirement. 6 new tests in `render.test.ts`, 5 in `tailwind-compiler.test.ts` (real subprocess, not mocked), 4 in `render-standalone-html.test.ts` (including the compile-failure fallback path).
